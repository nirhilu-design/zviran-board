# לוח פרויקט צבירן: הקמה על GitHub Pages ו-Supabase

המערכת בנויה משני חלקים:

| חלק | איפה הוא יושב | מה הוא עושה | עלות |
|---|---|---|---|
| האתר (`index.html`) | GitHub Pages | המסכים: דשבורד, תוכנית עבודה, קנבן, סוגיות, יומן שינויים | חינם |
| הנתונים וההתחברות | Supabase | שומר את הבקרות, מנהל מי מורשה להיכנס ומסנכרן שינויים בזמן אמת | חינם בשכבה הבסיסית |

כל משתמש נכנס עם המייל שלו בקישור חד-פעמי, בלי סיסמה. רק מיילים שמופיעים ברשימת המורשים רואים את הנתונים.

ההקמה לוקחת כחצי שעה, ועושים אותה פעם אחת.

---

## שלב 1: פתיחת פרויקט ב-Supabase

1. נכנסים ל-https://supabase.com ונרשמים, למשל עם חשבון GitHub.
2. לוחצים **New project**:
   - **Name:** `zviran-board`
   - **Database password:** בוחרים סיסמה חזקה ושומרים אותה. לא צריך אותה ביום-יום.
   - **Region:** `Central EU (Frankfurt)`, הקרוב לישראל.
3. מחכים כ-2 דקות עד שהפרויקט מוכן.

## שלב 2: יצירת הטבלאות וטעינת הנתונים

1. בתפריט הצד: **SQL Editor** ואז **New query**.
2. פותחים את הקובץ `supabase/schema.sql`. **לפני ההדבקה** מחליפים בסוף הקובץ את `PARTNER_EMAIL@example.com` במייל של השותף.
3. מדביקים ולוחצים **Run**. אמורה להופיע ההודעה `Success. No rows returned`.
4. **New query** נוסף: מדביקים את התוכן של `supabase/seed.sql` ולוחצים **Run**. כך נטענות 29 הבקרות ו-7 הסוגיות.

## שלב 3: העתקת פרטי החיבור

1. בתפריט הצד: **Project Settings** ואז **API** (במסכים חדשים: **Data API** ו-**API Keys**).
2. מעתיקים שני ערכים:
   - **Project URL**, משהו כמו `https://abcdxyz.supabase.co`
   - **anon public key**, מחרוזת ארוכה שמתחילה ב-`eyJ`. אם יש מפתח חדש מסוג `sb_publishable_...`, אפשר להשתמש בו במקום.
3. פותחים את `config.js` ומדביקים אותם במקום `YOUR_PROJECT` ו-`YOUR_ANON_KEY`.

> המפתח הזה ציבורי ומותר שיהיה גלוי באתר. את הנתונים מגינים כללי ההרשאות (RLS) שהוגדרו בשלב 2: מי שלא ברשימת המורשים לא רואה כלום.
> **לעולם לא** מדביקים בקבצים את ה-`service_role key`.

## שלב 4: העלאה ל-GitHub ופרסום ב-GitHub Pages

1. נכנסים ל-https://github.com ולוחצים **New repository**:
   - **Repository name:** `zviran-board`
   - **Public:** בחשבון חינמי, GitHub Pages עובד רק על ריפו ציבורי. הקוד יהיה גלוי, אבל **הנתונים לא**, כי הם ב-Supabase ומוגנים בהתחברות.
     אם יש לכם GitHub בתשלום (Pro, Team או Enterprise), אפשר לבחור Private.
2. בריפו החדש: **Add file** ואז **Upload files**. גוררים את כל התיקייה: `index.html`, `config.js`, `README.md` ותיקיית `supabase`. בסוף לוחצים **Commit changes**.
3. **Settings** ואז **Pages**:
   - **Source:** `Deploy from a branch`
   - **Branch:** `main` ו-`/ (root)`, ואז **Save**.
4. אחרי כדקה תופיע כתובת האתר, משהו כמו:
   `https://YOUR-USER.github.io/zviran-board/`

## שלב 5: חיבור כתובת האתר להתחברות

בלי השלב הזה, קישור הכניסה במייל לא יחזיר אתכם לאתר.

1. ב-Supabase: **Authentication** ואז **URL Configuration**.
2. **Site URL:** מדביקים את כתובת האתר משלב 4.
3. **Redirect URLs:** לוחצים **Add URL** ומוסיפים את אותה כתובת.
4. **Save**.

## שלב 6: כניסה ראשונה

1. פותחים את כתובת האתר, מזינים את המייל שלכם ולוחצים **שלחו לי קישור כניסה**.
2. במייל שמגיע (מ-Supabase Auth) לוחצים על הקישור.
3. הלוח נפתח. ההתחברות נשמרת בדפדפן, כך שלא צריך להתחבר בכל פעם.

שולחים לשותף את כתובת האתר, והוא נכנס באותה דרך עם המייל שלו.

---

## ניהול שוטף

**הוספת משתמש:** ב-Supabase פותחים **Table Editor**, ואז הטבלה `allowed_users`, ואז **Insert row**, ומזינים את המייל. אפשר גם להריץ ב-SQL Editor:
```sql
insert into allowed_users (email) values ('someone@zviran.co.il');
```

**הסרת משתמש:** מוחקים את השורה שלו מ-`allowed_users`. הגישה שלו נחסמת מיד.

**עדכון האתר:** מחליפים את `index.html` בריפו (**Add file** ואז **Upload files**). GitHub Pages מתעדכן תוך כדקה, והנתונים לא נפגעים.

**גיבוי:** כפתור **ייצוא לאקסל** במערכת מוריד קובץ עם שלושת הגיליונות. מומלץ לגבות פעם בשבוע. בנוסף, Supabase שומר גיבוי יומי.

## אם משהו לא עובד

| מה רואים | מה לבדוק |
|---|---|
| "המערכת עוד לא מחוברת למסד נתונים" | `config.js` לא מולא או לא הועלה לריפו |
| קישור הכניסה מחזיר לכתובת אחרת או לשגיאה | שלב 5: Site URL ו-Redirect URLs |
| "אין לך עדיין גישה ללוח" | המייל לא ב-`allowed_users`, או שנכתב אחרת. האותיות הגדולות לא משנות |
| המייל לא מגיע | לבדוק בספאם. שירות המייל המובנה של Supabase מוגבל לכמה מיילים בשעה. לשימוש רחב יותר מחברים SMTP של הארגון תחת **Authentication**, **Emails**, **SMTP Settings** |
| שינוי של השותף לא מופיע מיד | לרענן את הדף. אם זה חוזר על עצמו, לוודא ש-schema.sql רץ עד הסוף (סעיף 6 בקובץ מפעיל עדכונים בזמן אמת) |
| הפרויקט ב-Supabase "Paused" | בשכבה החינמית, פרויקט שלא נכנסו אליו שבוע נכנס להשהיה. נכנסים ל-Supabase ולוחצים **Restore**. בשימוש יומיומי זה לא קורה |
